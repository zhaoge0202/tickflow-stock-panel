# 模拟仓策略执行扩展

基于 `c63ee7648cc6c3b42c3a85e73212705d96d25b9d` 的 L2 组合式扩展。
前端位于 `frontend/src/custom/paper/`，复用已有 `/paper` 页面；后端经
`BackendExtensionRegistrar.include_router` 和 APIRouter lifespan 自动接入。
核心引擎、主应用、核心 API 和账务均无修改，无新增第三方依赖。

使用：创建独立账户 → 展开账户 →「策略买卖点跟单」→ 从回测候选、最近完成的回测、
配置/结果 JSON 或当前策略配置预览参数 → 确认绑定。回测配置须与账户初始资金一致。
首次空账户绑定时同步佣金、印花税、滑点；有历史成交的账户不改写费用。
当前策略来源沿用账户本金与费用，默认 10 仓、100% 敞口；精确参数请用回测来源。

## 执行契约

- 股票日线独立策略（Polars、历史策略、matrix_native）；收盘行情确认且数据日期为当日才执行。
  买卖委托均为 `next_open`。不把当日收盘之后才获得的信息回填为当日收盘成交，不重放过期日期。
- 复用 `ScreenerService.build_strategy_context`、`StrategyEngine.run`，使用逐股
  `entry_signal_hits` / `exit_signal_hits`，不用合并通知或池进出事件。
- 冻结 META 默认值、有效参数、过滤、评分、买卖点、风控、股票池、仓位和费用。
  回测参数按回测实际优先级处理：`config.params` 高于 META；不把全局 `override.params`
  再注入回测配置。当前策略来源使用 `resolve_params` 合并已保存调参。
- 参数超界/类型非法直接拒绝，避免回测自动钳制值而模拟仓使用原值。
  暂不支持 ETF、分钟策略/成交、叠加策略、市场环境过滤、独立全样本模式、自定义仓位策略、
  当日收盘/下一分钟成交；预览直接解释原因，不静默降级。
- 单个账户仅一个快照；首次绑定拒绝混有其他来源历史委托的账户。
  旧账户、旧事件规则完全保留；可显式确认停用空账户的旧规则后绑定。
  不自动迁移有持仓/挂单的账户。重新绑定必须无持仓和待成交委托。
- 策略及依赖的文件指纹、加载后定义与函数指纹变化、费用变更、冻结、外来委托、
  旧规则重新启用、缺失信号、坏状态均停止该账户，其他账户不受影响。
  这是冲突检测，不提供核心 API 层的独占账户权限。
- 单个 daemon worker 每 15 秒检查，只评估已启用绑定；同快照同日结果共用。
  SQLite 仅用于执行进程租约，不存另一套账户/台账；进程退出自动释放锁。
- 所有订单复用 `paper.create_order` 与 `PAPER_LOCK`，保留核心 T+1、手数、限价、
  费用、撮合、撤单、除权、净值规则。资金预算计入待成交买单，持仓数计入预占席位。
  持有中不因重复买点加仓，卖出不被买入冷却阻挡。
- 来源标签带快照/日期/标的/方向/原因的幂等指纹。下单后、检查点保存前退出，
  由原订单恢复去重；卖出意图先保存，可在 T+1 可卖后于下一交易日开盘前补交。
  同日已撤销/过期订单不重复提交，持仓仍在时次日可重试退出。
- 保护性风控使用真实入场成交价（不把佣金加进价格阈值）和新鲜原始价，记录观测峰值，
  除权同步换算；时间戳缺失/过期时等待新行情，不拿复权价或陈旧价下单。
  最大持有天数使用仓库实际交易日序列。所有账务仍只有核心 fills 这一份。

## 已知差异

- 模拟仓最低佣金 5 元，回测无此下限；相同费用参数不代表同净收益。
- 次日开盘单原本盘后记账，因此当天新开仓不会及时出现在实时持仓中。
- 回测可用历史 OHLC/分钟路径模拟风控触发与阈值成交；实时扩展只能观察轮询快照，
  也不会回填两次快照之间的理论成交价。停止后台或行情过期期间不保证保护性退出。
- 日线跟单需要行情服务确认当日收盘快照。确认失败会等待，不根据未确认缓存交易。
- 仓位按下单时权益和参考价预留；次日跳空、现金变化、涨跌停、缺行情、顺延会改变成交结果。
- 历史回测报告/候选没有保存策略代码版本，无法证明当前代码就是当年那一版。
  完整报告中的有效策略信息优先冻结；普通候选缺少的定义由当前版本解析并展示。
- 持续模拟仓没有历史回测的期末强平；五档未实现。

## 数据与升级

仅新增 `data/user_data/extensions/paper_execution/<account>.json`：版本 1、不可变快照、
信号日检查点、退出意图、风控峰值、最近 100 条决策记录。原子写，未知版本/损坏拒绝执行。
关闭或移除扩展不会删除账户、历史成交或撤销原委托。

扩展 API 前缀 `/api/custom/paper-execution`：`GET bindings/state`、`POST preview`、
`PUT binding`、`POST enabled`。绑定必须提交预览 revision，期间变动要求重新预览。
扩展客户端及查询键集中在 `executionClient.ts`；原账户数据复用 `api`、`QK.paper*`。
新订单记录变化只失效对应账户订单/总览与对比列表。没有新的策略结果缓存、行情采集或成交账本。

宿主依赖在 routes 生命周期边界提取为 engine/repo/quotes 引用，不修改 app.state 对象；
这些服务尚非版本化交易扩展契约。上游升级须重跑本扩展测试、原 paper/回测测试、
扩展装载/生命周期测试和前端构建，重点复核策略结果、参数优先级、模拟仓订单来源与撮合时序。
