# 实时行情与策略监控调度

行情采集、普通监控和每个策略分别推进。调度属于核心源码的 L3 改动，
不改变 Provider 路由、选股条件、评分、信号和模拟盘成交约束。

```text
行情线程：Provider → 日线与指标 → 发布当日快照 → SSE
                              ├→ 普通监控线程：价格、信号、板块、日期
                              ├→ 策略线程：(stock, Focus)
                              └→ 策略线程：(stock, Apex)
```

策略按 `(asset_type, strategy_id)` 分组，不依赖特定策略名称。
同组串行执行，每组最多保留一份待评估快照；计算期间有新行情时覆盖待办，
不会排队重放旧行情。一个策略完成后立即合并自己的结果并发布通知，不等待其他策略。
同一策略的多条监控规则仍沿用原引擎的逐条规则语义。

每组有独立的监控状态和可变矩阵缓冲。实时矩阵返回的是只读视图，
底层数据仍会在下一轮原地更新，因此不能跨策略共用同一个可变缓冲。
退出时释放缓冲；共享历史加载器和 StrategyEngine，不重复实现计算与数据源。

规则编辑、删除、策略注册变化和日线修正会使旧任务失效。成功结果按策略原子合并，
失败保留上一次有效结果；数据修正仍保留已提交的信号去重状态。
停止时清空待办并使计算中的任务失效，不强杀线程。已进入通知回调的投递允许完成。

事件继续经过原来的落盘、策略历史、SSE、系统通知和 Webhook 通道。
模拟盘沙盒信号只触发模拟盘；策略完成仅喂自动跟单，普通监控轮负责即时撮合，
避免每个策略完成都重复撮合。

ETF 和指数的指标全量路径缓存不含当日的原始历史输入，每资产最多 64 MiB。
历史文件指纹或日期变化、切换数据仓库、停止服务时失效；当日指标仍逐轮计算。

`GET /api/intraday/status` 新增可选诊断字段：

- `round_timing`：取数与普通监控调度耗时。
- `fetch_stages_ms`：网络、快照存储、日线、股票/ETF/指数指标分段耗时。
- `strategy_workers`：各策略运行与待办状态、上一轮耗时、完成时行情数据龄、线程异常。

历史配置和磁盘数据格式不变，SSE 事件与告警结构不变。
回滚时成套恢复 `quote_service.py`、`monitor.py`，移除新增调度模块即可；
无需迁移用户数据或修改策略文件。

线程隔离消除策略之间的串行等待，但不能缩短单个策略算法、Provider 网络请求，
也不能补齐分钟数据。冷矩阵准备仍经过 StrategyEngine 的共享锁；
部署后应比较相同市场时段的行情轮、各策略耗时、数据龄和 RSS，不能仅凭线程数验收。
