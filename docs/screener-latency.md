# 策略页计算与读取分离

本次针对策略页在历史重算时超时的问题修改核心调用链（L3）。
选股、评分、竞价与成交公式沿用原实现。

## 页面行为

- 选中策略只读取已有推荐历史，不再自动回填最近5个周期。
  需要历史补齐时，在“推荐历史”弹窗点击“补齐历史”。
- Focus三版本和盘后预选复用既有策略计算队列。页面立即取得计算状态，
  可见页面每2秒读取一次，结果就绪或失败后停止轮询。
- 计算中保留同日有效的正式缓存，显示“正在计算”，不会把占位空结果当作无命中。
  切日期或任务身份变化时，不沿用其他日期或旧任务的版本结果。
- 单策略明细仅更新该策略的价格和曾命中行；缓存读取不触发冷指标全量重建。

## 缓存与并发

历史缓存读取使用短状态锁。真实重算仍保持单份计算容量；
同一数据根、资产、日期与版本的并发请求共享计算，已有有效缓存不等待其他日期重算。
最多保留6个日期窗口，合计不超过512 MiB；以两个限制中先达到的为准。

缓存身份包含数据根、完整性修正版本及截至目标日期的指标代次。
显式清理不等待慢计算；裁剪或计算期间发生清理、历史修正时，旧结果不得返回或回填。
不同窗口仍按实际交易日裁剪，不能用自然日代替窗口长度。

实时监控的历史输入截止至当日前一天，当日行由已发布快照提供。
日线实时预览固定捕获一次当前快照，再拼接稳定历史；今日行情和分钟软更新不使
正在计算的预览永久失效。历史硬修正、定义或参数变更仍会拒绝旧任务。
实时快照不复用日级共享矩阵代次。

正式策略日期只缓存分区日期输入，每次按北京时间重新应用15:30门控。
因此跨收盘或跨日不会因30秒缓存继续返回昨日日期。

## API兼容

原调用默认保持同步行为：

- `POST /api/screener/preselect` 可选请求字段 `background: true`。
- `GET /api/screener/focus-versions` 可选查询参数 `background=true`。

后台响应保留原结果结构，新增可选字段：

```json
{"calculation":{"status":"pending","task_id":"..."}}
```

完成时 `status` 为 `ready`；错误使用HTTP错误响应，不能伪装成空结果。
任务按请求参数、策略定义、用户调参和依赖数据版本合并。
后台辅助视图不写未版本化的Focus快照、预选缓存或推荐历史；
原盘后管道及同步调用继续负责原有持久化路径。

## 验证与限制

必须验证慢任务阻塞时缓存仍可读、同请求只计算一次、清理后不复活旧帧，
以及持续实时写盘时今日预览最终能够完成。前端验证pending到ready、错误、跨日期，
并确认历史补齐仅由用户显式触发。

超过5秒的策略页等请求会记录方法、路径、耗时和状态码；不记录查询参数、正文或凭据。
该计时覆盖服务器处理时间，浏览器连接排队仍需结合网络面板判断。

这轮消除请求同步等待与隐式历史回填，不保证单个策略算法或磁盘IO一定更快。
冷计算与部分矩阵内核仍共享计算资源，Windows实际收益需部署后在相同时段验证。
